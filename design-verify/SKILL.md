# design-verify

把"像不像"变成"对不对"。

肉眼对比只能发现明显的错，发现不了**静默硬编码**——写了一个 `#5C5C5C` 而不是 `$ink-2`，页面看起来一模一样，但主题一切换就崩。这类错误正是反复返工的根源，所以验收必须是机器判定。

**先读 [references/constraints.md](references/constraints.md)** 的**第五节**（允许保留自定义值的三种情况与豁免格式）、**第九节**（失控预算，迭代 3 轮就停）与**卡点 2**（失败项怎么报）。术语见 [references/glossary.md](references/glossary.md)。

---

## 前提：拿到值集合

从目标仓库 `docs/design-system-inventory.md` 读出合法值集合——颜色、间距、排版、圆角那几张表里的所有取值和 token 名，亮暗值都算。

**表结构与字段含义见 [references/inventory-schema.md](references/inventory-schema.md)**（与 `design-probe` 共用同一份契约）。三种异常分开处理：

- **没有盘点或元信息里的源文件已变** → 先跑 `design-probe`，不要拿过期集合硬验。
- **表结构与契约不符**（缺列、表头改名）→ 不要猜列的含义，按卡点 2 说明格式不符。
- **读出来是空集合** → 这是最危险的一种，因为空集合会让每一项看起来都“无可比对”而静默通过。**集合为空必须当作验收未能执行报告，不是通过。**

**没有值集合就没有判据**——这种时候说明情况并停下来，不要“看起来没问题就算通过”。

### 先看盘点范围

取值之前先读元信息里的 `盘点范围`。标为 `部分` 时，未扫类别的表**不是空集合，是未知**：

- 本次改动涉及的类别在已覆盖范围内 → 正常验收。
- 涉及未扫类别 → 列入「未验证的部分」并建议补扫，**不判通过也不判失败**。

把未扫当成空集合会把正常项目误报为无体系，反过来则会静默放行。字段缺失时按 `完整` 处理（旧文档兼容）。详见 `references/inventory-schema.md`。

## 第一层 · 静态扫描（默认必跑）

只扫**本次改动的文件**。扫全仓库会被历史遗留淹没，然后所有人开始无视这个门禁。

改动范围取自 `git diff`（未提交的改动 + 本次分支相对基线的改动），或本次会话中实际编辑过的文件。

### 扫什么

在改动的行里找这些**字面量**：

- 颜色：`#rgb` / `#rrggbb` / `#rrggbbaa` / `rgb(...)` / `rgba(...)` / `hsl(...)`
- 尺寸：`font-size` / `line-height` / `padding` / `margin` / `gap` / `border-radius` / `width` / `height` 上的裸 `px` 值
- 字重：`font-weight` 的裸数字

### 怎么判

值能在集合里找到对应 token → **通过但提示**："这里可以用 `$ink-2` 代替 `#5C5C5C`"。
值不在集合里 → **失败**，走卡点 2。

### 三种豁免

`references/constraints.md` 第五节允许保留自定义值的三种情况——固定像素尺寸无对应工具类、主题相关的资源切换、词汇表里确实没有匹配项。

**识别方式是固定前缀**，存在于被豁免行紧邻的上一行：

```
/* design-exempt: <原因> */      CSS / SCSS
<!-- design-exempt: <原因> -->  模板
```

匹配到该前缀 → 记为「已声明豁免」列进报告（带上原因文本）；**没有该前缀 → 算失败**，旁边有其他注释也不算。

不要把任意相邻注释当成豁免说明。`/* 卡片容器 */` 这类普通注释极常见，认它就等于豁免机制形同虚设。

这条设计是有意的：让"我知道我在硬编码"和"我忘了用 token"能被区分开。前者是有意识的取舍，后者是缺陷。

### 不扫什么

第三方库源码、生成物、`node_modules`、构建产物、与本次设计无关的改动（如同时改了的接口调用）。**token 定义文件本身**（盘点源文件里的变量声明）里的 hex 是合法定义，不当失败。

### 可选轻检（有动效注记或演示状态机时做，默认随静态层附带）

不要求像素级动效对比。只做存在性核对，记进报告「可选轻检」：

- 运行记录 / Figma 注记里的动效，对应 CSS `animation` / `transition`（或等价）是否存在；有 `prefers-reduced-motion` 处理更佳。
- 状态清单里的非理想态，在本次改动页面上是否可到达（演示页：点击/脚本能切到；非演示：有对应 UI 分支即可）。

缺一项 → **提示**（不单凭此项判整次验收失败），并建议补或记降级。

## 第二层 · 运行时扫描（页面能跑起来时跑）

静态层抓不到的：写的是 token，但被继承 / 覆盖 / 优先级问题弄成了别的值。这一层专抓这个。

### 起页面

**先查 terminals 有没有已经在跑的 dev server**，有就复用。不要盲目再起一个——重复起 server 会占端口、会让你验的是另一个进程。

浏览器工具用 `playwright` 或 `cursor-ide-browser` 都可以，按当前会话方便选。

页面实在跑不起来 → **降级**：只做静态层，明确提示需要人工核对，并写进报告。不要因为跑不起来就跳过整个验收。

### 扫什么

定位到**本次新增或改动的元素子树**（从改动的组件根节点进入，别扫整页）。

对子树内的元素读 computed style：`color`、`background-color`、`border-color`、`font-size`、`line-height`、`font-weight`、`padding-*`、`margin-*`、`gap`、`border-radius`。

与值集合比对，不在集合内即失败。

### 为什么不扫整页

整页会被噪音淹没：动画库注入的中间值、第三方组件的内联样式、浏览器默认值——全都不在你的 token 集合里。假阳性一多，这个门禁三天就被无视了。

**宁可漏报，不可淹没。**

### 亮 / 暗都要扫

语义变量的意义就在于跟随主题。只扫亮色等于没验证暗色那一半——切换主题再扫一遍。

## 埋点模式（默认关闭）

需要**逐节点与 Figma 精确比对**时才启用：落地时给元素加 `data-figma-node-id`，验收时按节点 ID 一一对应比对。

因为它要改业务代码，**默认不做**，只在明确要求"精确对齐"时启用；用完在提交前移除，或确保构建期剥离。

## 失控预算

**验收 → 修复 → 再验收，超过 3 轮就停下来汇报**：已经试过什么、现在差在哪、建议怎么办。

不要无限迭代。有些差异是设计本身超出了当前实现能力，磨十轮也磨不出来，早点说清楚比默默改二十个文件有用。

失败本身不打断（不是卡点），超预算才汇报。

**长页面档的 3 轮按模块算，不按整页算。** 十几个模块共用 3 轮预算时，每个模块均摊不到一轮；而同一类错误在第二个模块就拦住的话，后面十个根本不会重复。

---

## 长页面档：随填随验，不等到最后

被 `design-pipeline` 阶段 5b 叫进来时，**一次只验刚填完的那一个模块文件**，只跑静态层，不起页面。

等十几个模块全做完再验会一次冒出几十条偏差，而且分不清哪条来自哪个模块——那时修一条要先找一遍上下文。更关键的是：未被拦下的错误会随**样板模块**传给后面每一个模块，候选修复量是模块数的倍数。

逐模块验收的结果写回运行记录里那个模块的完成状态旁边（通过 / 待修）。

全页完成后**还要再跑一次完整验收**（含运行时层 + 亮暗两轮）。逐模块静态层看不到的是跨模块问题：相邻 section 的上下边距叠加、整页滚动下的背景色断层。

## 输出

```markdown
## 验收结果：通过 / 失败 / 降级（页面未能启动）

### 静态层
扫描文件 N 个，改动行 M 行
- 失败 X 处：<文件:行> 值 <#5C5C5C> 不在词汇表内
- 可优化 Y 处：<文件:行> <#1a1a1a> 建议改用 <$ink-1>
- 已声明豁免 Z 处：<文件:行> 原因 <design-exempt: 后面的文本>

### 运行时层
扫描子树 <选择器>，元素 N 个，亮/暗各一轮
- 失败 X 处：<选择器> 的 color 实际渲染为 <rgb(...)>，不在词汇表内

### 未验证的部分
（页面未启动 / 缺少某状态的入口 / 需要人工核对的地方）
```

失败项按 `references/constraints.md` 卡点 2 处理——不要自作主张挑一个近似的 token 替上去。
