# 盘点文档格式契约

`docs/design-system-inventory.md` 的格式规定。**唯一定义源**，`design-probe`（写方）与 `design-verify`（读方）都引用它。

这份契约存在的理由：`design-verify` 把颜色 / 间距 / 排版 / 圆角那几张表**当合法值集合直接读**。格式散了验收就失效——而且是静默失效，它会读到空集合然后"全部通过"。

术语见同目录的 `glossary.md`。

---

## 落在哪

写进**目标仓库**的 `docs/design-system-inventory.md`，不是 skill 仓库。

一个目标仓库一份。多 app 的 monorepo 若各 app 主题不同（如 `--q-primary` 被覆盖成不同值），在表的「来源」列里区分，不要拆成多份文档。

---

## 头部元信息（必须有）

没有元信息就无法判断新鲜度，盘点会退化成"看起来可信的过期快照"。

```markdown
<!-- 生成时间: 2026-07-30T16:00+08:00 -->
<!-- 盘点范围: 完整 -->
<!-- 源文件:
  src/styles/theme.scss
  src/styles/variables.sass
  src/packages/index.ts
  quasar.config.js
-->
<!-- Figma fileKey: ABC123 -->
```

**源文件清单要列全**——`design-probe` 靠比对这些文件的 mtime / 内容哈希决定是否重扫。漏列一个，那个文件改了也不会触发重扫。

### 盘点范围字段

取值只有两种：`完整`，或者 `部分` 加上已覆盖与未覆盖的类别。

```markdown
<!-- 盘点范围: 部分（仅间距、颜色）-->
<!-- 未扫: 排版、圆角、组件库、Figma 侧、Code Connect -->
```

部分盘点来自 `design-probe` 的最小可用盘点路径（小修场景）。

**读方必须先看这一行再取值集合。** 本契约的根本规则是"空集合当验收未能执行，不是通过"，而部分盘点里缺席的表恰好也表现为空集合。两者必须区分开：

| 情形 | 含义 | 验收怎么处理 |
|---|---|---|
| 范围=完整，某表为空 | 项目真的没这类 token | 报告「无词汇表，未能执行」，走卡点 2 |
| 范围=部分，该类在已覆盖内 | 扫过且可用 | 正常验收 |
| 范围=部分，该类在未扫内 | 本次没扫，不代表没有 | 报告「该类未盘点，本轮不判定」，建议补扫 |

三者在文件里长得一模一样，只有这一行元信息能区分。没有它就只能二选一：把未扫当成空（本可用的项目被报成无体系），或把空当成未扫（真没体系的项目静默放行）。

没有这一行字段时，**按 `完整` 处理**——这是旧盘点文档的兼容行为。

## 正文表格

表头字段**不要改名、不要减列**，`design-verify` 按列取值。没有的信息填 `—`，不要删列。

### 颜色

| token | 亮色值 | 暗色值 | 工具类 | 来源 |
|---|---|---|---|---|
| ink-1 | #1a1a1a | #ffffff | .text-ink-1 | src/styles/theme.scss |

亮 / 暗必须成对填。只有一个值的（不随主题变的固定色）在暗色列填 `同亮色`，**不要留空**——留空会被读成"暗色下无合法值"。

### 间距

| token | 值 | 工具类 |
|---|---|---|
| md | 12px | q-pa-md / q-ma-md |

值带单位。多个工具类用 ` / ` 分隔。

### 排版

| token | 字号/行高/字重 | 工具类 |
|---|---|---|
| body1 | 16/24/400 | .text-body1 |

字号 / 行高 / 字重用 `/` 连接、不带单位（默认 px），与 Figma 的 `Text/XXX` 惯例对齐。

### 圆角

| token | 值 | 工具类 |
|---|---|---|
| radius-md | 8px | rounded-borders |

### 组件库

| 组件 | 用途 | Code Connect |
|---|---|---|
| BtDialog | 弹窗 | ✅ src/components/BtDialog.figma.ts |
| BtSwitch | 开关 | ❌ 缺映射 |

有映射填 ✅ 加路径，没有填 ❌ 加原因。**覆盖率低不是错误**，如实记即可（走记账，不是卡点）。

### 图标

不用表格，写清四件事：字体 set 名、**命名前缀**（写错前缀 = 图标不显示或显示错图）、SVG 资源目录、暗色变体命名约定。

### 断点与响应式惯例

断点名与取值；「设备是移动端」与「视口窄」分别用什么判断；项目各区域用哪套；PC / 移动是分文件还是单文件自适应。

**两套断点取值不一致时必须写明**——这是最容易静默出错的地方。

### Figma 侧

库名与 `libraryKey`、变量命名规律、可用组件清单。

---

## 结尾：推导规律（必须写）

只列清单不够。要写**工具类名怎么从 token 名推出来**，例如：

> 类名 = `text-` + `$headings` 的 key 原样（小写），数字直接贴在词后不含连字符。所以 `body1` → `text-body1`，而 `text-body-1` 是不存在的死类。

有了规律，遇到表里没列的 token 也能推对；没有规律，表外的一切都要重新探测。

---

## 读方注意（design-verify）

- 合法值集合 = 上述各表里的**所有取值与 token 名**，亮暗值都算。
- 元信息缺失或源文件已变 → 盘点过期，**先跑 `design-probe`**，不要拿过期集合硬验。
- 表结构与本契约不符（缺列、表头改名） → 不要猜，按 `constraints.md` 卡点 2 处理并说明格式不符。
- **没有值集合就没有判据**，这时说明情况并停下，不要"看起来没问题就算通过"。
