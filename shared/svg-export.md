# SVG 导出与暗色变体

从 Figma 整节点导出 SVG、以及把灰阶插画改成暗色变体时的实测经验。

**只在真的要导出 SVG 资源时读**——落地流程里前两档（图标字体名、`currentColor` 内联单色图标）用不到这份文件。

---

## 先确认要不要走导出

图标与资源分三档，导出是**最后一档**：

1. 能对应图标字体名 → 直接用，不导出。注意 set 的命名前缀，以项目现有写法为准。
2. 自定义**单色**图标 → 导出 SVG，**优先 `currentColor` 内联**——自动跟随主题与文字色，免维护两份。
3. **多色**插图 / logo → 导出资源；实在无法用 `currentColor` 时才产出暗色变体。

第 3 档才需要下面这些。能停在第 2 档就别往下走：`currentColor` 内联省掉的是**一整套暗色变体的维护成本**。

---

## 坑一：祖先画板的 chrome 会混进来

用 `download_assets(defaultFormat:"svg")` 导单个节点时，导出的 SVG 常把**父级画板 / 画布的背景**一起画进去：

- 整块底色矩形（如 `<rect .. fill="#EDEDED"/>`）
- 巨型画布矩形（坐标像 `M-2148 -342…`，一眼就能认出来）
- 带 `filter=drop-shadow` 的白卡片
- content 层的白底矩形

**必须删掉这些 chrome**，只留真正的插画层——通常是带 `clip-path` 的那个 `<g>`，让背景透明。

删完**本地栅格化肉眼核对**，不要只看代码判断：

```bash
qlmanage -t -s 480 -o <dir> x.svg
```

暗色图在白底截图上看不出问题，先临时垫一个深色 `<rect>` 再截图，核对完删掉。

---

## 坑二：别动结构性的 `fill="white"`

SVG 里有两处 white **不是可见颜色**，而是遮罩 / 裁剪语义（白 = 显示）：

- `<mask id=".." fill="white">`
- `<clipPath><rect fill="white"/></clipPath>`

做暗色重映射时若把它们跟着一起改黑，**遮罩失效、图形残缺**。而且这种残缺常常只在某个主题下出现，容易漏掉。

改色前把这两处**占位保护**（替换成一个不会被规则命中的临时串），改完再还原。

---

## 暗色变体 = 有序颜色重映射

**不是 invert。** 纯 invert 会出「死黑纸卡」——原本柔和的白色纸张变成纯黑块，比不做还难看。

按下面的顺序逐类映射，**顺序本身有意义**：

| 原始元素 | 映射目标 |
|---|---|
| 高光 `fill="white" fill-opacity=".8"` | 保留为浅色（**必须最先处理**） |
| 线稿描边（深灰 `#5C5C5C`） | 提亮成浅灰，在深底上可读 |
| 纸卡 / 镜片 `fill="white"` | 深卡片色（如 `#2E2F35`） |
| 柔光底块（近白 `#F6F6F6`） | 极暗低对比色 |
| 中灰件（`#ADADAD`） | 略降的中灰 |
| `fill="black" fill-opacity` 的阴影 | 翻成 `white` 低透明 |
| `<mask>` / `<clipPath>` 里的 white | **保持不变** |

两个顺序陷阱：

- **高光要先于纸卡处理**。都是 `fill="white"`，如果先做纸卡替换，半透明高光会被一起改成深色卡片色，画面失去层次。
- **阴影的方向要翻转**。暗色底上的阴影是**浅色**而不是更深的黑——照搬黑色阴影等于什么都没画。

---

## 主题切换

用主题选择器（如 `body.body--dark`）切两张 `<img>` 的 `display`。**纯 CSS，不用 JS。**

这也正是「三种豁免」里的第二种（主题相关的资源切换）。`design-verify` 静态层会扫到这里的自定义类，**必须按固定前缀声明豁免**（格式见 `constraints.md` 第五节）：

```css
/* design-exempt: 亮/暗两张插画靠主题选择器切 display，无对应工具类 */
.illustration-light { display: block; }
```

没有 `design-exempt:` 前缀就算失败，写了其他说明文字也不算。
